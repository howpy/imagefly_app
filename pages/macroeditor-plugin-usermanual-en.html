Macro Editor (Prototype) - User Manual

Dragonfly Prototype Apps · Macro Editor (Prototype)

Version 1.0 · 2026-10-28


1. Introduction

Macro Editor (Prototype) is my personal experimental Dragonfly plugin for analysing, organizing and modifying recorded Python macros. It can be installed in Dragonfly 2025.1 or 2027.1 and opened from Utilities ▸ Macro Editor (Prototype), immediately below Macro Builder.

Important disclaimer: this plugin is a personal experiment. It is not an official feature developed, certified or supported by Object Research Systems (ORS) or Dragonfly. It is provided only for Dragonfly users to learn, practise and evaluate macro-editing ideas. Always keep the original macro and validate edits on a copy of the data.

I designed it because recorded macros can contain many low-level operations: publishing objects, display ranges, overlay text, view state and repeated updates may be mixed with the steps that actually process data. The official Macro Player is suited to running macros, and Macro Builder to recording or constructing them. Macro Editor focuses on understanding, inspecting, refactoring and reusing an existing macro.

  • Macro Player primarily runs a macro in its recorded order; Macro Editor adds pre-run inspection of structure, parameters and dependencies, plus editing of a copy.
  • Macro Builder primarily records or constructs a macro; Macro Editor imports an existing recording and organizes its steps and parameters.
  • Macro Editor (Prototype) adds a high-level overview, step refactoring, parameter tables, editor projects and runtime object binding.

2. Use cases

  • Summarize a recording with tens or hundreds of steps as higher-level loading, preprocessing, segmentation, ROI/label, measurement, export and view/annotation stages.
  • Find and change thresholds, file paths, sizes, iteration counts, label numbers and output options in one place.
  • Duplicate, rename, move, disable or delete steps to create a more readable and maintainable macro copy.
  • Adapt a macro that was tied to one set of objects or files for use with other data.
  • Review unknown code, input dependencies, parameter expressions and original source before execution.

“Display-related” does not mean “irrelevant to the result.” A window range may later be read as a threshold, the current label or view plane may select what is processed, and a screenshot may be the intended output. Automated analysis therefore supplies candidates, never a guarantee that a step is safe to remove.

3. Installation & enabling

1. Install a Prototype Apps online package or App Store version that includes Macro Editor.

2. Confirm that Macro Editor (Prototype) is selected in the component list.

3. Completely exit and restart Dragonfly after installation so it can discover the plugin and its menu action.

4. Open Utilities ▸ Macro Editor (Prototype). It appears immediately below Dragonfly's native Macro Builder.

5. To disable it later, use the Prototype Apps Menu Item Manager or rerun the installer and adjust the selected components.

The plugin supports Dragonfly 2025.1 and 2027.1. Interface preferences may be shared across versions, while each Dragonfly user profile still needs the corresponding plugin files installed.

4. Runtime environment & first-run setup

Macro Editor runs inside the Dragonfly process and uses Dragonfly's bundled PyQt6 and MacroPlayer. It requires no separate virtual environment, GPU, internet connection or language model, and performs no first-run download.

  • Import reads text and parses Python AST metadata only. It does not execute, import or deserialize the opened macro.
  • The edited macro executes in the current Dragonfly session only after you click Step or Run all and confirm.
  • The shared settings system remembers interface preferences. Macro content, dynamic object bindings and parameter presets belong to a project you explicitly save.

For a first exercise, open the bundled examples/parameter_demo.py. It performs simple arithmetic only, creates no Dragonfly objects and writes no files.

5. Interface

Files and edit history

Open macro imports a recorded .py; Save macro as exports a .py usable by the native Macro Player; Open/Save project stores the editable Macro Editor state, presets and bindings; Undo/Redo applies to the current editing session.

Step list

The left pane contains every original step and its category. You can search, select multiple steps, include or omit disabled steps, and enable, disable, move, duplicate, rename or delete. Hide display steps changes only what the editor shows; it does not change macro execution.

High-level workflow

The central workflow does not make one node for every recorded step. It groups consecutive work into higher-level stages and uses arrows only for stage order. Click a stage to see all its original steps in Stage overview; then click a member to edit the exact step.

Stages can represent input/loading, preprocessing, segmentation, ROI/label editing, measurement, output/export, view/annotation, display updates and other operations. Very complex workflows are explicitly coarsened into mixed phases rather than becoming another unreadable forest of lines.

For example, a 118-step text-overlay recording is summarized as two stages: create and publish the annotation (2 steps), then update its content/display (116 steps). The summary is navigation only; source and execution order are unchanged.

Inspector

The right tabs are Parameters, All parameters, Source, Changes, Validation, Run / inputs, Log, and Stage overview. They edit one step, survey parameters, show read-only source, track edits, report warnings, bind inputs and execute, display runtime logs, and navigate stage members.

6. How to use

1. Back up the original .py macro, then use Open macro… to import a copy.

2. Read the high-level workflow. Click a stage and verify its original members in Stage overview.

3. Select an original step and inspect its actual purpose in Parameters and Source. Unknown APIs and opaque Python are preserved and labelled, not guessed into a new operation.

4. Edit an expression and click Apply parameters. Python strings need quotes, for example 'output.tif'.

5. Organize with move, duplicate, rename, enable, disable or delete. Use Focus dependencies to inspect the conservative prerequisites of an output step.

6. For display simplification, click Simplify display… and review each candidate and reason. Prefer hiding or disabling first; never assume all candidates may be deleted.

7. Use Save project… to retain an editable project and Save macro as… for a separate native macro. Do not overwrite the only original recording.

8. In Run / inputs, refresh current published objects and bind missing inputs. Step through or test on a data copy before adapting the workflow to other data.

8. Output

  • Native macro (.py): current edited steps, execution flags and preserved unknown code, suitable for Dragonfly Macro Player.
  • Macro Editor project (.json): editable document, editor state, presets and explicitly saved bindings for later work.
  • Results in the current Dragonfly session: produced only after explicit Step or Run all; depending on the macro these may be Channels, ROIs, MultiROIs, Meshes, measurements or files on disk.

The high-level workflow and stage-member list are analysis views. They are not written back into the macro and are not a replacement executable workflow format.

9. FAQ & troubleshooting

  • Macro Editor is missing from the menu: confirm the component was selected during installation and fully restart Dragonfly. Look under Utilities, below Macro Builder.
  • The workflow looks too summarized: click a stage to see every member. The high-level graph intentionally omits individual nodes; exact edits remain in the step list and Stage overview.
  • The workflow contains Other operations: that phase contains an unknown API, opaque Python or work that cannot be classified reliably. Inspect its members and source; do not disable it blindly.
  • A parameter causes a syntax error: check Python expression syntax. Quote text paths/names; a Windows path can use a raw string such as r'C:\data\a.tif'.
  • A runtime object cannot be found: refresh objects in Run / inputs, make sure the target is published and visible in Dragonfly's object list, then bind it again.
  • Stop does not end immediately: Stop is cooperative between steps. A long native API call cannot be safely interrupted before it returns.
  • The result changed after simplification: restore disabled/deleted steps, preferably with Undo or a saved project. Compare data, geometry, labels and measurements on the same input, not just the screen appearance.

10. Notes & known limitations

  • This is a personal experimental prototype, not an official tool. Classification, dependency analysis and simplification suggestions are conservative aids and cannot replace professional judgement about an imaging workflow.
  • Import does not execute code, but running the edited macro can change Dragonfly objects and overwrite output files named by the macro.
  • Undo/Redo reverses editor document changes only. It cannot roll back data processing already completed in Dragonfly.
  • Stop takes effect at step boundaries and cannot forcibly terminate a native Dragonfly operation already in progress.
  • Complex control flow, dynamic Python, unknown APIs and opaque expressions are preserved where possible and explicitly marked. The plugin does not pretend to understand them fully.
  • High-level stages are a navigation summary, not a complete data-dependency graph and not a decision about safe deletion.
  • Before using a macro with other data, recheck object bindings, paths, voxel sizes, units, thresholds, label numbers and output destinations.

11. References

Refer to the bundled README, the side-effect-free examples/parameter_demo.py, and Dragonfly's native Macro Player and Macro Builder. When reporting experimental results, include the Dragonfly version, whether the original macro was preserved, the relevant step title, and whether the issue occurred during import, editing, saving or explicit execution. Do not put customer data, sensitive paths or confidential macro content in a public report.
